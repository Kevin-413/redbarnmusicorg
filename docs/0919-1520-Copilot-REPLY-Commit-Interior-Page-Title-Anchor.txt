TECHNICAL FINDINGS RECORDED

1. Avada Header Builder uses direct menu IDs, not theme_location
   Avada's actual front-end header render calls `wp_nav_menu()` with
   `'menu' => 19` (the site's single registered menu, resolved by ID) rather
   than `'theme_location' => 'main_navigation'`, even though that same menu is
   assigned to the `main_navigation`/`mobile_navigation`/`sticky_navigation`
   locations. A filter that only checks `$args->theme_location` silently never
   fires on the real site (confirmed via direct instrumentation: theme_location
   was empty string on every real request). Fixed by resolving the menu ID(s)
   assigned to those three locations via `get_nav_menu_locations()` and matching
   `$args->menu` against them, in addition to checking theme_location, so the
   filter works regardless of which calling convention a given call site uses.

2. widget_display_callback required for Avada's footer Text widgets
   Core's `widget_text_content` filter — the documented, expected hook for
   rewriting a Text widget's rendered content — never fires at all for Avada's
   footer widget areas (confirmed by instrumenting the filter: zero invocations
   logged for any widget on a real page load, despite the widgets clearly being
   the standard core Text widget by id_base). `widget_display_callback` (which
   fires earlier, before `WP_Widget::widget()` runs, and is part of the more
   fundamental `WP_Widget::display_callback()` wrapper every registered widget
   goes through) does fire and was used instead, rewriting `$instance['text']`
   directly before Avada renders it.

3. Home link and external Facebook link verified unchanged
   Confirmed via direct HTML fetch (`curl`) against the live-rendered page,
   both before and after the fix:
   - Home link: both its absolute (`http://redbarnmusicorg-avada.local/`) and
     relative (`/`) forms remain exactly `href="/"` / the bare domain root —
     no `#page-title` appended, matching the required "must keep loading at
     the true top" rule.
   - External Facebook link in the footer "Connect" widget
     (`https://www.facebook.com/groups/FriendsOfTheRedBarn/`) is byte-for-byte
     unchanged in both instances found in the rendered HTML.
